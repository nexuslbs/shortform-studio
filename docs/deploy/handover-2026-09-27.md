## Ordered steps

### Step 1 (Human): Google account, YouTube channel, enable YouTube Data API v3

* **Who:** Human (Workstation Lab).
* **Action:** sign in as the account above (do not create a new account), create
  the YouTube channel, then in Google Cloud Console create/select a project and
  enable the YouTube Data API v3.
* **Exact values:** account `hermes@nexuslbs.org`; channel display name
  `OmniStack`; API `YouTube Data API v3`.
* **Verify:**
  * the Google account shown top-right is `hermes@nexuslbs.org`;
  * the channel exists (for example `https://www.youtube.com/@OmniStack`) and its
    name is `OmniStack`;
  * Google Cloud Console > APIs & Services > Enabled APIs & services lists
    `YouTube Data API v3`.

### Step 2 (Human): OAuth2 desktop client, scopes, and the two secret names

* **Who:** Human, on the account from Step 1.
* **Action:**
  1. Configure the OAuth consent screen: External, Testing is fine, add the
     account as a test user.
  2. Add BOTH scopes:
     * `https://www.googleapis.com/auth/youtube.upload`
     * `https://www.googleapis.com/auth/youtube.readonly`
  3. Create credentials > OAuth client ID > Application type: **Desktop app**.
  4. Run the installed-app OAuth flow (for example `google-auth-oauthlib`'s
     `InstalledAppFlow.run_local_server`) to mint an access token. Access tokens
     expire (roughly 1 hour), so keep the refresh token/flow reusable.
  5. Create an API key: Credentials > Create credentials > API key. Restrict it to
     `YouTube Data API v3` (and to the host IP if possible).
  6. Store both values in the omniagent secrets store (API, or the dashboard):
     * `YOUTUBE_OAUTH_TOKEN` (the OAuth access/refresh token)
     * `YOUTUBE_API_KEY` (the restricted API key)
* **Exact values:** secret names only, `YOUTUBE_OAUTH_TOKEN` and
  `YOUTUBE_API_KEY`. Never paste a value into this file, a commit, a chat message,
  or a shell you log.
* **Verify:**
  * `GET /secrets` lists both names;
  * a repo search finds no credential material:
    `git grep -nE 'ya29\.|AIza[0-9A-Za-z_-]{20,}'` returns nothing new;
  * `scripts/preflight.sh` reports `YOUTUBE_OAUTH_TOKEN is set` without printing
    the value.

### Step 3 (Human): review the video and the disclosure (plan touchpoint)

* **Who:** Human.
* **Action:** watch the produced MP4, read the description, confirm the
  AI/synthetic disclosure is present and accurate, confirm the title and
  description are not misleading, then approve.
* **Exact files:**
  * `out/roman-concrete/video.mp4` (1080x1920, 37.5 s, H.264/yuv420p + AAC)
  * `out/roman-concrete/description.txt` (title, summary, disclosure, #Shorts, hashtags)
  * `out/roman-concrete/metadata.json` (`status.containsSyntheticMedia=true`,
    `status.selfDeclaredMadeForKids=false`)
  * `out/roman-concrete/qa-report.json` (17/17 PASS)
* **Verify:** `python3 -m shortform qa --slug roman-concrete` exits 0; the
  disclosure sentence is visible and truthful; the title is 38 characters; the
  operator explicitly approves.
* **Watch item (review risk R3):** the disclosure sentence currently sits after
  the title and summary. That is acceptable today because the compliance
  mechanism is the API flag `containsSyntheticMedia` and no affiliate link is
  present. Before adding affiliate links, move the disclosure to the first
  paragraph, above the "...more" fold.

### Step 5 (Human approves, then agent): live private upload

* **Who:** the human approves; the command may be run by the human or by the
  agent with the token in the environment.
* **Commands:**
  ```bash
  export YOUTUBE_OAUTH_TOKEN="<token from the secrets store>"
  python3 -m shortform publish --slug roman-concrete --live --privacy private
  ```
* **Verify:**
  * the command exits 0 and prints `UPLOAD OK id=<REAL_VIDEO_ID> privacy=private`;
  * `out/roman-concrete/publish-result.json` records the real `video_id`;
  * in YouTube Studio the video is **private**, the "altered or synthetic content"
    disclosure shows as set, and "Made for kids" is No;
  * record the real id here for Step 7: `REAL_VIDEO_ID = ____________________`.

### Step 6 (Human): YouTube Studio warning/strike check

* **Who:** Human.
* **Action:** in YouTube Studio, check the video and the channel for any warning,
  strike, or policy notice, and confirm the disclosure and kids flag.
* **Verify:** the warnings/strikes count is 0. If it is not 0, stop and apply the
  kill criteria in `docs/deploy/measurement-2026-09-27.md`.
* Only after this check may privacy be changed to `unlisted`/`public`.

### Step 7 (Agent): start measurement

* **Who:** Agent (scheduled from the host; see the measurement doc).
* **Action:** schedule `scripts/measure_daily.sh <REAL_VIDEO_ID>` with
  `YOUTUBE_API_KEY` in the environment.
* **Verify:** `data/metrics/<REAL_VIDEO_ID>.jsonl` receives one line per UTC day.

### Step 8 (Human): what "monetised" actually requires (YPP)

* **Today (2026-09-27):** 1,000 subscribers AND either 10,000,000 qualified public
  Shorts views in the last 90 days OR 4,000 qualified public watch hours in the
  last 12 months.
* **From 2027-02-01 (new applicants):** 1,000 subscribers AND either 20,000,000
  qualified public Shorts views in 90 days OR 8,000 qualified public watch hours
  in 365 days.
* Shorts ad revenue is paid through AdSense only after YPP acceptance and the $100
  payout threshold; Shorts RPM is typically about $0.01 to $0.10 per 1,000 views.
* Source: `docs/research/platform-rules-2026-09-27.md`.

### Step 9 (Agent): cost so far

* Pipeline cash cost so far: about **$0.00 per video**.
* YouTube Data API v3 `videos.insert` costs **1 quota unit per upload** and the API
  is **free within the default quota** (a separate bucket of about 100 upload
  calls/day); the measurement call uses the same free quota.
* Local tools only: `ffmpeg`/`ffprobe`, `espeak-ng`, Pillow. **No paid API was
  used** (no Google Cloud TTS, no image-generation API, no LLM token spend); the
  script is a hand-authored JSON file.
* Expected marginal cost after handover: still about $0 per video at this volume.
